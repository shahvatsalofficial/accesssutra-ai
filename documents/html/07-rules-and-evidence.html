    Rules and evidence model

    All 18 rules, how they map to candidate WCAG criteria, and the evidence ladder behind every statement.

    18 rules. Full table with severity, candidate WCAG criteria and remediation: see docs/RULES.md in the repository.

    All rules#

    RuleSeverityCandidate WCAGWhat it flagsFix
    AS-DOC-001moderate2.4.2Page title is missingAdd a concise, descriptive <title> in <head>.
    AS-DOC-002moderate3.1.1Document language is missingSet an appropriate nonempty lang attribute on <html>.
    AS-DOC-003moderate3.1.1Document language code looks malformedUse a valid BCP 47 language tag such as "en" or "pt-BR".
    AS-FORM-001serious3.3.2, 4.1.2Form control lacks a detectable accessible nameUse an associated visible <label>, or an appropriate accessible name where necessary.
    AS-FORM-002moderate3.3.1, 3.3.3Invalid form control lacks a detectable error associationAssociate clear error text using aria-describedby or aria-errormessage and verify the message is announced.
    AS-FORM-003moderate1.3.1, 3.3.2Label "for" does not point to an existing elementPoint label for= at the id of the control it describes, or wrap the control in the label.
    AS-IMG-001serious1.1.1Image is missing alt attributeProvide an appropriate alt text, or alt="" for genuinely decorative imagery.
    AS-BTN-001serious4.1.2Button lacks a detectable accessible nameAdd visible button text or an appropriate accessible name.
    AS-LINK-001serious2.4.4, 4.1.2Link lacks a detectable accessible nameGive the link descriptive text or an appropriate accessible name.
    AS-FRAME-001moderate2.4.1, 4.1.2Frame lacks a titleGive each iframe a short, descriptive title attribute.
    AS-ID-001moderate-Duplicate id may break referencesGive each element a unique id and retest labels and ARIA relationships.
    AS-ARIA-001moderate4.1.2ARIA reference does not resolve to an elementPoint ARIA ID references to existing elements and verify accessible name/description.
    AS-ARIA-002serious4.1.2, 2.4.3Focusable element is inside aria-hidden or hidden contentRemove focusable controls from hidden subtrees, or stop hiding them; verify with a keyboard.
    AS-FOCUS-001moderate2.4.3Positive tabindex may disrupt focus orderPrefer DOM order and tabindex="0" where needed; verify real keyboard navigation.
    AS-KEY-001moderate2.1.1Clickable nonsemantic element needs keyboard reviewUse a native button or link; manually verify keyboard activation and focus.
    AS-VIEW-001serious1.4.4Viewport meta may block zoomRemove user-scalable=no and any maximum-scale below 2; verify text resize and pinch zoom.
    AS-MEDIA-001moderate1.4.2, 2.2.2Autoplaying media without controls needs reviewAvoid autoplay, or provide visible controls to pause, stop or mute; verify with people.
    AS-REFRESH-001moderate2.2.1, 3.2.5Meta refresh may remove user control of timingRemove timed refresh/redirect or give users a way to turn off, adjust or extend it.

    Rule families#

    FamilyRulesQuestion
    DocumentAS-DOC-001, 002, 003Does the page have a title and a valid language?
    FormsAS-FORM-001, 002, 003Do fields have names, error association and valid label targets?
    NamesAS-IMG-001, AS-BTN-001, AS-LINK-001, AS-FRAME-001Do images, buttons, links and frames expose a name?
    ReferencesAS-ID-001, AS-ARIA-001, AS-ARIA-002Are ids unique, ARIA references resolvable, focusable items not hidden?
    KeyboardAS-FOCUS-001, AS-KEY-001Positive tabindex? Click handlers on non-interactive elements?
    Zoom and timingAS-VIEW-001, AS-MEDIA-001, AS-REFRESH-001Zoom blocked? Autoplay? Timed refresh?

    Evidence model#

    SourceStrengthStatement allowed
    Static scanLimited"Candidate found in source at line N"
    Browser run (axe-core, Tab samples)Moderate for what axe covers"axe-core reported rule X on N nodes"
    Human observationDepends on reviewer and environment"Reviewer R recorded status S in environment E"
    NothingNone"Not tested"

    The tool never converts weaker evidence into a stronger statement. Empty findings produce "accessibility remains unverified".

    Where tools disagree#

    A placeholder-only input is flagged by AccessSutra (AS-FORM-001) but accepted as a name by axe-core. The two are intentionally different: placeholders disappear on input and are poorly supported as names. Decide with a human check.
